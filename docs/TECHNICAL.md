# TECHNICAL.md — Zsh Profile v3.3

Architecture, module reference, design decisions, and extension guide for the Fedora-first Zsh configuration.

---

## Architecture

The shell configuration is organized as a thin entry point (`.zshrc`) that sources 15 module files in strict dependency order. Each module lives in one of 4 directories that communicate its architectural layer:

```
~/.zshrc                     # Entry point (51 lines, symlinked by installer)
~/.zsh_modules/             # Module directory (symlinked by installer)
├── boot/                    # Startup chain (order-critical)
│   ├── prompt.zsh           # ① P10k Instant Prompt (MUST be first)
│   ├── timer-start.zsh      # ② Wall-clock timer start
│   ├── theme.zsh            # ⑬ P10k theme (MUST be last substantive source)
│   ├── compile.zsh          # ⑭ Bytecode compilation (background)
│   └── timer-end.zsh        # ⑮ Timer end + zshrc-time display
├── core/                    # Shell foundation (no external deps)
│   ├── environment.zsh      # ③ PATH dedup, user bins, XDG dirs
│   ├── shell.zsh            # ④ Zsh options, 50K history, dedup
│   └── security.zsh         # ⑤ History credential filter + sudo wrapper
├── plugins/                 # Framework & plugin loading
│   ├── cache.zsh            # ⑥ Version-fingerprint plugin init cache
│   ├── omz.zsh              # ⑦ Oh My Zsh framework, conditional plugins
│   └── lazy.zsh             # ⑧ zsh-defer deferred source (optional)
└── tools/                   # User-facing productivity
    ├── aliases.zsh          # ⑨ eza, grep, navigation, system cleanup
    ├── nvidia.zsh           # ⑩ NVIDIA/Fedora GPU helpers + CUDA opt-in
    ├── functions.zsh        # ⑪ up, mkcd, nf, gcom, lazyg, sedi, extract, bk, port
    └── local.zsh            # ⑫ ~/.zshrc.local overrides (pre-theme)
```

Numbers indicate load order. This contract is enforced by the order of `source` calls in `.zshrc`.

### Symlink Model

The installer creates two symlinks:

```bash
~/.zshrc       → repo/.zshrc          # Entry point
~/.zsh_modules → repo/modules/        # Module directory
```

Before creating symlinks, existing regular files (not symlinks) at these locations are backed up with a timestamp suffix (`.bak.YYYYMMDD_HHMMSS`).

## Module Reference

### boot/prompt.zsh (① — MUST be first)

Sources Powerlevel10k's instant-prompt cache from `$XDG_CACHE_HOME/p10k-instant-prompt-${(%):-%n}.zsh`. This file is generated by P10k on the first shell start and contains the prompt pre-rendered to a file, which is sourced as raw bytes — no parsing, no execution.

**Constraint:** This must be the first line of Zsh code that does any I/O. No `echo`, `printf`, command substitution, or module source may precede it. Violations cause P10k to silently disable instant prompt on the next shell start.

### boot/timer-start.zsh (②)

Loads `zsh/datetime` module (`zmodload`) to enable the `$EPOCHREALTIME` parameter (float seconds with microsecond precision). Stores start time in a global `_zshrc_start_s` variable consumed later by `timer-end.zsh`.

If `zsh/datetime` is unavailable (minimal Zsh builds), sets `_zshrc_start_s=""` — the timer becomes a no-op rather than erroring.

### core/environment.zsh (③)

Two responsibilities:

1. **Path deduplication**: `typeset -U path PATH fpath FPATH ld_library_path LD_LIBRARY_PATH` — treats each array as a set, removing duplicates automatically. Must run before any PATH modifications to prevent repeated entries when `.zshrc` is reloaded.

2. **XDG Base Directories**: Sets `XDG_CONFIG_HOME`, `XDG_CACHE_HOME`, `XDG_DATA_HOME` to defaults if not already set. Modern CLI tools (zoxide, fzf, bat) auto-respect these.

Also prepends user-local bins to PATH: `~/.opencode/bin`, `~/.local/bin`, `~/bin`, `~/.spicetify`.

### core/shell.zsh (④)

Configures Zsh options and history:

- `AUTO_CD`: cd by typing directory name alone
- `EXTENDED_GLOB`: `#`, `~`, `^` operators for pattern matching
- History options: `SHARE_HISTORY` (share across sessions in real-time), `HIST_IGNORE_ALL_DUPS`, `HIST_SAVE_NO_DUPS`, `HIST_EXPIRE_DUPS_FIRST`, `HIST_REDUCE_BLANKS`
- `HISTSIZE=50000`, `SAVEHIST=50000`, `HISTFILE="${ZDOTDIR:-$HOME}/.zsh_history"`
### core/security.zsh (⑤)

Two independent security layers:

**History Filter** (`zshaddhistory` hook): Blocks commands from being saved to HISTFILE based on 7 pattern groups:

| Pattern | Matches |
|---------|---------|
| `(TOKEN\|SECRET\|PASSWORD\|...) =` | Env var credential assignments |
| `https?://user:pass@host` | URL-embedded credentials |
| `--(token\|password\|secret\|...) <val>` | Flag-based credentials |
| `ssh-keygen`, `ssh-add`, `/etc/ssh/`, `.ssh/id_*` | SSH key material |
| `gpg --passphrase`, `gpg --export-secret` | GPG passphrase exposure |
| `aws configure`, `aws iam create-key` | AWS credential operations |
| Commands >4096 chars | Binary blobs, base64 payloads |

The function converts input to uppercase for case-insensitive matching. Returns 1 (block) or 0 (allow).

**`-p` was removed** from the flag-based patterns because it produced too many false positives: `ssh -p 2222 host`, `ping -p 80 host`, `tar -p file.tar.gz` are all legitimate commands that triggered the filter.

**Sudo Guard** (`sudo-last` function): Explicit command (doesn't shadow the `sudo` binary). Previews the last history command via `fc -ln -1`, asks for confirmation, and checks against a blocklist:

| Pattern | Blocks |
|---------|--------|
| `rm -rf /` | Root filesystem wipe |
| `mkfs` | Device formatting |
| `dd of=` | Direct disk writes |
| `chmod -R 777 /` | World-writable root |

Blocked commands return exit code 1 with an error message. Use `--yes` to skip the confirmation prompt in non-interactive scripts.

### plugins/cache.zsh (⑥)

**Problem:** `zoxide init zsh` and fzf key-binding sourcing run on every shell start, adding ~150-200ms. These commands rarely change (only when tools update).

**Solution:** Cache their output to `$XDG_CACHE_HOME/zsh_plugins_init.zsh` with a version-based fingerprint. Flow:

1. **Generate fingerprint**: `tool --version | head -1` for each watched tool → concatenate → `cksum` (CRC32 + byte count)
2. **Check staleness**: Compares cache file's modification time against a `.last_check` marker. Only re-checks fingerprint once per 24 hours (TTL). This avoids running `tool --version` on every shell start.
3. **Rebuild**: If fingerprint mismatch, rebuild cache via `mktemp` → validate tool output → `mv` (atomic overwrite). Each tool's init is validated by exit code before inclusion; failed tools leave a comment marker. Trap cleans up temp on interruption.
4. **Source**: Cache file is sourced directly (fast path).
5. **Bytecode compile**: Cache is compiled to `.zwc` in background (`zcompile ... &!`) for faster loading on next shell start.

Watched tools: `zoxide`, `fzf`.

### plugins/omz.zsh (⑦)

Configures Oh My Zsh with performance-focused flags:

- `ZSH_DISABLE_COMPFIX=true`: skips compaudit (~7ms saved). Safe on single-user machines.
- `zstyle ':omz:update' mode disabled`: disables OMZ auto-update prompt via the recommended zstyle method.
- `ZSH_THEME=""`: Powerlevel10k is loaded separately via `boot/theme.zsh`.

Core plugins: `git` (aliases, branch info), `history` (history-related aliases).

Conditional plugins: `zsh-autosuggestions` and `zsh-syntax-highlighting` are added to the OMZ plugin list **only** when `zsh-defer` is not available. When zsh-defer is present, these plugins are loaded lazily via `lazy.zsh`.

### plugins/lazy.zsh (⑧)

Optional deferred loading via `zsh-defer` (from Powerlevel10k's author). When installed:

1. Sources `zsh-defer.plugin.zsh`
2. Defers `zsh-autosuggestions` via `zsh-defer source ...`
3. Defers `zsh-syntax-highlighting` via `zsh-defer source ...`

**Ordering constraint:** zsh-syntax-highlighting must load AFTER zsh-autosuggestions. Loading in reverse causes highlighting to fail on suggestion text. `zsh-defer` preserves this by deferring each source sequentially.

### tools/aliases.zsh (⑨)

Conditionally defines aliases (guarded by `command -v`). Groups:

| Group | Aliases | Guard |
|-------|---------|-------|
| File listing (eza) | `ls`, `ll`, `la`, `l`, `lt` | `eza` |
| Colorized grep | `grep --color=auto`, `fgrep`, `egrep` | `grep` |
| Navigation | `home`, `docs`, `dtop`, `reload` | none (static) |
| System cleanup | `dnf-clean`, `apt-clean`, `brew-clean`, `flatpak-clean`, `sys-clean` (platform-adaptive) | `dnf`, `apt`, `brew`, `flatpak` |

The `sys-clean` alias has 3 variants: first available package manager (dnf > apt > brew).

### tools/nvidia.zsh (⑩)

**Startup rule:** Never runs `nvidia-smi` while sourcing. All queries are on-demand — GPU diagnostics don't affect the sub-150ms startup target.

Aliases (guarded by `nvidia-smi`):

| Alias | Output |
|-------|--------|
| `nvidia-ver` | GPU name, driver version, total VRAM |
| `nvidia-stat` | Full CSV: temp, utilization, power, memory, pstate |
| `nvidia-quick` | Compact temp/utilization/memory/power |
| `nvidia-watch` | `watch -n2 nvidia-smi` |
| `nvidia-procs` | GPU compute processes |

Functions (guarded by `command -v nvidia-smi`, defined only on NVIDIA systems):

| Function | Purpose |
|----------|---------|
| `nvidia-temp` | GPU temperature (°C) |
| `nvidia-mem` | Used/total GPU memory |
| `nvidia-power` | Power draw + limit |
| `nvidia-clock` | Graphics/memory clock + pstate |
| `nvidia-persistence [on\|off]` | Set persistence mode |
| `nvidia-plimit <watts>` | Set power limit |
| `nvidia-akmods` | Rebuild NVIDIA kernel modules (with confirmation) |

RPM helpers (guarded by tool availability):

| Alias | Guard |
|-------|-------|
| `nvidia-rpm` | `rpm` |
| `nvidia-kmod` | `lsmod` |
| `nvidia-update-check` | `dnf` |

CUDA functions (explicit opt-in, never auto-loaded):

| Function | Purpose |
|----------|---------|
| `cuda-env` | Add /usr/local/cuda to PATH + LD_LIBRARY_PATH |
| `cuda-use <version>` | Switch to specific CUDA version (e.g., `12.6`) |
| `cuda-gcc13` | Set NVCC_CCBIN for GCC 13 compatibility |

CUDA is deliberately not added to PATH automatically — avoids global LD_LIBRARY_PATH side effects.

### tools/functions.zsh (⑪)

**Navigation:**

| Function | Usage | Behavior |
|----------|-------|----------|
| `up [n]` | `up 3` — go up 3 levels | Builds `../../..` path |
| `mkcd <dir>` | `mkcd project/src` | `mkdir -p` + `cd`, rejects control chars |

**File creation:**

| Function | Usage | Behavior |
|----------|-------|----------|
| `nf <file>` | `nf temp.txt` | `touch --` with name validation |

**Git workflow:**

| Function | Usage | Safety checks |
|----------|-------|---------------|
| `gcom "msg"` | Stage all + commit | Verifies git dir, rejects clean repo (no empty commits) |
| `lazyg "msg"` | Commit + optional push | Detached HEAD detection, 10s push timeout, non-interactive skip |

**Utilities:**

| Function | Usage | Pattern |
|----------|-------|---------|
| `sedi "s/a/b/" <file>` | Safe in-place sed | `cp` backup → `mktemp` → `sed` → `mv` (atomic) |
| `extract <archive>` | Extract any format | Case/esac on extension: tar.gz, zip, rar, 7z, zst |
| `bk <file>` | Timestamped backup | `file.bak.YYYYMMDD_HHMMSS` |
| `port [num]` | Port checker | Linux: `ss -tulpn`, macOS: `lsof -i`, validates 1-65535 |

### tools/local.zsh (⑫)

Conditionally sources `~/.zshrc.local` if it exists. This file is machine-specific and never tracked in version control. Use cases: work-specific aliases, secret env vars, local paths.

### boot/theme.zsh (⑬ — MUST be last substantive source)

Loads Powerlevel10k theme from 3 possible locations (first found wins):
1. `~/powerlevel10k/powerlevel10k.zsh-theme`
2. `${ZSH_CUSTOM}/themes/powerlevel10k/powerlevel10k.zsh-theme`
3. Falls through silently if neither exists

Then sources `~/.p10k.zsh` if present (generated by `p10k configure` wizard).

**Constraint:** Must be sourced after all plugins, aliases, and functions. The P10k theme renders the prompt — any configuration after it that affects prompt segments won't take effect.

### boot/compile.zsh (⑭)

Bytecode compilation via `zcompile` (Zsh's built-in tokenizer → bytecode parser). Pipeline runs in background (`&!` — disowned, no job notification):

- Compiles `~/.zshrc` to `~/.zshrc.zwc`
- Batch-compiles all modules in `~/.zsh_modules/**/*.zsh` inside a single subshell (avoids spawning N processes)

Only recompiles when source files are newer than their `.zwc` counterparts. The function cleans up after itself (`unset -f _zsh_compile_all`).

### boot/timer-end.zsh (⑮)

Finalizes boot timing and provides the `zshrc-time` command:

```
zshrc-time() — displays shell load time with color-coded thresholds
- <150ms  → green (excellent)
- <200ms  → green (good)
- <500ms  → yellow (acceptable)
- ≥500ms  → red (slow)
```

Calculation: `$(( (EPOCHREALTIME - _zshrc_start_s) * 1000 ))` → integer milliseconds via `printf "%.0f"`. Cleans up `_zshrc_start_s` after use.

## Design Decisions

### Modular 15-File over Monolithic (ADR-001)

| Before (v2.2) | After (v3.0+) |
|---------------|---------------|
| 342-line monolithic .zshrc | 51-line entry point + 15 modules |
| 10 loosely-delimited sections | 4 architectural layers with strict order |
| Implicit ordering constraints | Explicit numbered source calls |
| Hard to find specific config | Module name = purpose, directory = layer |

**Negative consequences:**
- ~1-3ms overhead from 15 `source` calls (mitigated by `.zwc` bytecode)
- Cross-module globals must be maintained (`typeset -g`)
- New contributors must learn the load order contract

### Subdirectory Layers over Numbered Prefixes

An earlier iteration used flat numbered files (`01-prompt.zsh` through `14-boot-end.zsh`). This was abandoned because:
- Numbers communicate order but not purpose
- Inserting a file between 07 and 08 requires renumbering
- Users scanning the directory don't know which files are "core" vs "plugins"

**Decision:** 4 subdirectories (layers) with purpose-communicating filenames. Order is documented in `.zshrc`, not encoded in filenames.

### Plugin Cache over Raw OMZ Sourcing

Raw `zoxide init zsh` + fzf key-binding sourcing adds ~150-200ms per shell start. The cache saves their output to a file after version fingerprint validation. Result: 30-50% faster boot when cache is warm.

### Version Fingerprint over Path Fingerprint

Original cache used `command -v <tool>` (binary path) as fingerprint. On Fedora, DNF updates tools in-place — the path doesn't change after `dnf upgrade`. The cache would never rebuild.

**Fix:** Use `tool --version 2>/dev/null | head -1` piped through `cksum`. The version string changes on upgrade, and `cksum` produces a short, collision-resistant hash.

### TTL-based Staleness over Flock Locking

Some configurations use `flock` (file lock) to prevent multiple simultaneous shells from rebuilding the cache. This project uses a simpler approach: a `.last_check` marker file with a 24-hour TTL. The cache rebuilds at most once per day.

**Rationale:** Tools only change on DNF upgrades (infrequent, predictable). The TTL approach avoids:
- External dependency on `flock` (BSD `flock` has different syntax)
- Race condition handling code
- Lock file cleanup on crash

### `SHARE_HISTORY`

`SHARE_HISTORY` is the only explicitly set history-sharing option. It syncs history across all sessions in real-time via IPC notification, providing immediate cross-session visibility — commands from one session appear in others without delay.

### `-p` Removed from History Filter

`-p` was in the original pattern set but caused false positives on legitimate commands: `ssh -p 2222 host`, `ping -p 0x80 host`, `tar -p file.tar.gz`. These are common daily commands that were silently dropped from history.

**Decision:** Remove `-p` entirely. The remaining patterns (`--token`, `--password`, `--secret`, `--api-key`, `--access-key`) cover flag-based credential leaks. `-p` is too ambiguous across tools.

### sudo-last over sudo() Wrapper

The original `sudo()` function hijacked the `sudo` binary, intercepting calls to `sudo !!`. This was confusing — users expected normal `sudo` behavior. The `sudo-last` function is an explicit, separate command: previews the last history entry, confirms with the user, and blocks dangerous patterns. `--yes` flag skips the prompt for script use.

### CUDA Opt-in over Global `LD_LIBRARY_PATH`

Some configs add `/usr/local/cuda` to PATH and `LD_LIBRARY_PATH` unconditionally. This breaks:
- Python virtual environments (CUDA libraries shadow system libraries)
- Side-by-side CUDA version switching
- Non-GPU workflows that don't need CUDA at all

**Decision:** `cuda-env` is a function that must be called explicitly. `cuda-use <version>` switches between installed versions. Both modify only the current shell session.

### Batch Compile over N Parallel Processes

Original code spawned one `&!` process per module (15 background processes). Current code wraps all module compilations in a single subshell: `( for src in ...; do zcompile; done ) &!`.

**Result:** One background process instead of 15. Same parallelism (the loop runs sequentially but in the background).

### Atomic Write Pattern (mktemp → write → mv)

Used consistently in `cache.zsh` and `functions.zsh` (sedi):

```bash
tmp=$(mktemp) || return 1
trap "rm -f '$tmp'" INT TERM
# ... write to tmp ...
mv "$tmp" "$target"
trap - INT TERM
```

**Why:** Writes to a temp file in the same filesystem, then `mv` (atomic on POSIX) renames it. Prevents partial writes, corrupted files from crashes, and predictable temp names.

### Principles (from ADR-001)

| # | Principle | Applied In |
|---|-----------|-----------|
| P1 | Zero output before P10k Instant Prompt | boot/prompt.zsh |
| P2 | Internal globals use `_` prefix; cross-module use `typeset -g` | timer-start.zsh, cache.zsh |
| P3 | Clean up internal state after use | cache.zsh:132, timer-end.zsh:12, functions.zsh:113+117 |
| P4 | One concern per file | All 15 modules |
| P5 | Fail gracefully on missing dependencies | aliases.zsh, cache.zsh, omz.zsh, lazy.zsh |
| P6 | Atomic write pattern for all cache/backup ops | cache.zsh, functions.zsh |
| P7 | Self-documenting: why not what | All modules |

## Installation Internals

### `install.sh` Flow

```
main()
  ├─ --install flag? → do_quick_install() directly
  ├─ --uninstall flag? → do_uninstall() directly
  └─ Interactive menu:
       [1] Install      → confirmation → do_quick_install()
       [2] Quick Install → do_quick_install() (no prompts)
       [3] Uninstall    → confirmation → do_uninstall()
       [q] Quit

do_quick_install():
  1. detect_pkg_manager()       → auto-detect: dnf/apt/pacman/zypper
  2. do_install_required()      → install zsh, git
  3. do_install_optional()      → install eza, fzf, zoxide
  4. do_install_omz()           → curl Oh My Zsh (skips if exists)
  5. do_install_p10k()          → git clone powerlevel10k (skips if exists)
  6. do_install_plugins()       → git clone zsh-autosuggestions, syntax-highlighting, zsh-defer
  7. do_link_config()           → backup → ln -sf
  8. do_set_shell()             → chsh -s zsh
  9. write_install_state()      → persist install metadata
```

### Curl-pipe Detection

When piped from curl, `BASH_SOURCE[0]` is empty. `ensure_repo()` handles this by:
1. Checking if `REPO_DIR` is set (local script execution)
2. Checking if `~/.zsh_profile_repo/.git` exists (previous clone)
3. Cloning the repo to `~/.zsh_profile_repo`

### Uninstall Behavior

`do_uninstall()` removes symlinks, bytecode (`.zwc`), and cache files. It preserves installed packages and Oh My Zsh — clean removal without affecting the user's system.

## Extending the Config

### Adding a New Module

1. Create the file in the appropriate `modules/<layer>/` directory
2. Add a `source "$_M/<layer>/<file>.zsh"` line at the correct position in `.zshrc`
3. Follow the load order contract:
   - Before `boot/theme.zsh` if the module defines functions/aliases
   - After `boot/compile.zsh` only if the module is post-processing

### Adding Aliases

Edit `modules/tools/aliases.zsh`. Guard optional commands with `command -v`:

```zsh
if command -v bat &>/dev/null; then
  alias cat='bat --theme=Dracula'
fi
```

### Adding Tools to the Plugin Cache

Append to `_TOOLS_WATCHED` in `modules/plugins/cache.zsh` and add init logic inside `_zsh_build_plugin_cache()`:

```zsh
typeset -ga _TOOLS_WATCHED=(zoxide fzf bat)
# Inside _zsh_build_plugin_cache:
if command -v bat &>/dev/null; then
  printf '\n# --- bat ---\n' >> "$tmp"
  # bat does not need init, but if a tool had an init command:
  # bat cache --build >> "$tmp" 2>/dev/null
fi
```

### Local Overrides

Create `~/.zshrc.local` with machine-specific config. It's sourced automatically (by `tools/local.zsh`) before the theme loads, so prompt customizations in `.p10k.zsh` can reference local settings.

### Load Order Rules

| File position | Permitted content |
|---------------|-------------------|
| Before `cache.zsh` | No plugin/init dependencies |
| Between `omz.zsh` and `theme.zsh` | Aliases, functions, completions |
| After `theme.zsh` | Post-processing, timers, cleanup |
| After `compile.zsh` | Compilation, finalization |
